# Funding and support

Financial contributions are optional and do not buy project access, governance rights, priority, guaranteed support, or promised features. Donation size never affects maintainer authority or how contributions are reviewed.

The staged plan is to begin active fundraising only after the project meets its Development Preview/Alpha gate and an external tester can reproduce the basic workflow. If a verified funding route is then enabled, voluntary support may help cover development tools and AI subscriptions, hardware and testing costs, project expenses, and the maintainer's livelihood. The project is not represented as a charity, and contributions must not be described as tax-deductible without a legal basis.

There is no verified payment destination configured yet, so the project is **not currently accepting donations through an official online channel**. The owner must select an eligible platform, complete and test payout setup, review its fees and terms, and then add only verified destinations to `.github/FUNDING.yml`. Do not add personal payment links or placeholder usernames.

Non-financial contributions are welcome as the repository foundation is completed: focused code and documentation PRs, reproducible issue reports, Orange Pi/ARM64 hardware tests, controller/display validation, and controlled compute support. Never provide passwords, unrestricted remote access, ROMs, BIOS, saves, or credentials as a contribution.

The owner should keep private records of contributions, platform fees, and project expenses, and publish sustainable summaries when appropriate. Do not promise a response time or feature delivery that the project cannot maintain.
